FMS (Faculty Monitoring System): dummy accounts
================================================

Password for every account:  Fm@2026!

These accounts exist only in DEBUG builds (running from Visual Studio). They are created the first time the app
launches. To get them again, uninstall the app from the emulator and run it again.
Sign-in is by ID (exactly 5 characters, not case sensitive).

Notes
-----
- When you add a school or department in Services\AcademicCatalog.cs, the app creates a dummy Dean, Chairperson
  and Faculty for it automatically. Chairperson and Faculty IDs follow catalog order (chr08, fac08, ...) and Dean IDs are dean2, dean3, ...
  They are listed in this file only if you add them by hand.
- Every department and school already has a dummy Chairperson and Dean, so registering a Chairperson or Dean
  shows the "role is occupied" warning. Faculty, READS Scholar and IMS Personnel can still register.
- Dummy accounts are already email-verified and approved. Their emails are <id>@fms.test (for example fac01@fms.test),
  which do not exist, so "Forgot password" for them only works in simulated email mode (the code is shown on screen).
- To test the approval flow, register a new Faculty (pick a department, verify the email code), then sign in as that
  department's Chairperson (chr01..chr07) and open the Approvals tab. A new READS Scholar (ID up to 10 characters) is approved by ims01 on the Approvals tab.

- The password is also in Services\SeedData.cs. Keep the GitHub repository private.
